# 回复合规审核

## 元信息

| 字段 | 值 |
|------|-----|
| ID | `de_local_02_sk04` |
| 类型 | **`atomic`（原子技能）** |
| 所属员工 | 口碑捍卫者 |
| 能力族 | 检测判断型 · 合规审查 |
| 复杂度 | `S` |
| 阶段 | `P0` |
| 复用度 | 高（点评回复生成、差评灭火、好评感谢流程的发布前必经关卡） |
| 资产形态 | 纯提示词（无运行时依赖） |

## 能力描述

商家回复发布前的合规预审。按三类红线扫描：**诱导删改评价**（含分句/变体/谐音，按语境合并判定，依据平台评价诚信规则与《反不正当竞争法》第八条）、**过度承诺与虚假信息**（《广告法》第九条绝对化用语、无边界责任承诺、编造荣誉）、**隐私与不当互动**（《个人信息保护法》脱敏检测、过度亲昵称呼、公开区对线）。三级判定（🔴 红线 / 🟡 警告 / 🔵 提示），每条给出可直接替换的合规改法，并把「补偿与评价物理隔离」作为私信话术的通关标准。

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `text` | string | ✅ | 待审文本（公开回复 / 私信话术 / 补偿方案文案，多条用编号分隔） |
| `platform` | string | ⬜ | 美团 / 点评 / 抖音 / 小红书 / 通用 |
| `policy` | string | ⬜ | 补偿授权口径，核对金额与折扣是否超授权 |

## 输出规格

- `verdict`：受检文本量 / 三级计数 / 整体判定（通过 / 修改后发布 / 退回重写）
- `violations`：违规清单（级别 / 原文片段 / 命中红线 / 依据 / 合规改法）
- `suggestions`：整体改写方向与需人工核实的事实项

## 使用步骤

### 方式一：直接使用（最快）

1. 打开任意支持自定义提示词的 AI 工具
2. 复制 `prompt.txt` 的**全部内容**作为系统提示词
3. 粘贴待审回复 + 平台 + 补偿授权口径
4. 得到分级违规清单与合规改法

### 方式二：在主流平台导入

| 平台 | 导入方式 |
|------|---------|
| **Coze / 扣子** | 新建 Bot → 人设与回复逻辑 → 粘贴 `prompt.txt` |
| **WorkBuddy** | 新建 Skill → 填入 `prompt.txt` 内容 |
| **Dify** | 新建应用 → 提示词编排 → 粘贴 `prompt.txt` |
| **Claude** | 新建 Project → Instructions → 粘贴 `prompt.txt` |

## 边界（不做的事）

- ❌ 不编造违规项——「欢迎再给一次机会」等合规表述不误报
- ❌ 不提供谐音、拆字、图片文字等规避检测的写法——属违规协助
- ❌ 不审核定价、成本等实质经营信息
- ❌ 不构成法律意见；食安与人身伤害回复一律转人工/法务定稿

## 调用示例

**输入**（`examples/input.json`）：两条私信话术，第一条含「改好评返现 20」。

**输出**（要点）：红线 1 项（诱导删改评价，依据平台评价诚信规则 + 《反不正当竞争法》
第八条）、提示 1 项（「后厨已换供应商」需核实）——整体判定**退回重写**，
改法 = 补偿与评价物理隔离后重发。

- 好评感谢回复生成
- 月度口碑报告
