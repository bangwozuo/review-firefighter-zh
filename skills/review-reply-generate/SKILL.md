# 点评回复生成

## 元信息

| 字段 | 值 |
|------|-----|
| ID | `de_local_02_sk02` |
| 类型 | **`atomic`（原子技能）** |
| 所属员工 | 口碑捍卫者 |
| 能力族 | 文本生成型 · 评价回复 |
| 复杂度 | `S` |
| 阶段 | `P0` |
| 复用度 | 中 |
| 资产形态 | 纯提示词（无运行时依赖） |

## 能力描述

评价细节驱动的个性化回复生成。按星级三档策略（4-5 星复购催化剂 / 3 星改进金矿 / 1-2 星危机处置）分档撰写，每条回复**强制引用评价中的至少 1 个具体细节**（菜名、店员、等位时长等），杜绝万能模板。好评档 50-100 字含轻引导（≤1 次、无交换条件），中差评档 60-120 字走四要素结构。服务「差评 2 小时黄金响应窗口、回复率 100%」的平台排序目标，命中升级信号（12315 / 媒体曝光 / 律师函 / 集体投诉 / 食物中毒）自动剔除转人工。

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `reviews` | string | ✅ | 评价原文（含星级与文字细节） |
| `root_cause` | string | ⬜ | 已判定根因；缺省按星级分档 |
| `policy` | string | ⬜ | 补偿授权边界（差评档适用） |
| `batch` | array | ⬜ | 批量模式 [{id, stars, text}]，自动做开头句去重 |

## 输出规格

- `replies`：逐条回复（星级档位 / 引用细节 / 回复文案 / 字数 / 处置动作）
- `root_cause`：分档判定依据
- `recovery`：补救动作清单（差评档），涉及补偿标注需人工确认
- `escalation`：转人工清单，无则为空

## 使用步骤

### 方式一：直接使用（最快）

1. 打开任意支持自定义提示词的 AI 工具
2. 复制 `prompt.txt` 的**全部内容**作为系统提示词
3. 提供评价原文（批量时给 batch 数组）
4. 得到分档回复文案与批次质量自检结果

### 方式二：在主流平台导入

| 平台 | 导入方式 |
|------|---------|
| **Coze / 扣子** | 新建 Bot → 人设与回复逻辑 → 粘贴 `prompt.txt` |
| **WorkBuddy** | 新建 Skill → 填入 `prompt.txt` 内容 |
| **Dify** | 新建应用 → 提示词编排 → 粘贴 `prompt.txt` |
| **Claude** | 新建 Project → Instructions → 粘贴 `prompt.txt` |

## 边界（不做的事）

- ❌ 不生成「好评返现」「评价换菜」及变体 —— 平台明令禁止，触及《反不正当竞争法》
- ❌ 无细节引用的万能模板回复视为不合格，必须重写
- ❌ 不公开承诺补偿金额，不泄露客户可识别信息
- ❌ 不编造整改动作、荣誉、销量数据
- ❌ 升级信号评价不自动回复，只出转人工标记

## 调用示例

**输入**（`examples/input.json`）：

```json
{
  "reviews": "等位 40 分钟才吃上，孩子都饿哭了，虽然味道还行但体验太差",
  "policy": "无补偿授权，仅回复"
}
```

**输出**（要点）：2 星档，引用「等位 40 分钟」「孩子饿哭」细节，四要素结构 96 字；
处置动作 = 转差评灭火流程 + 建议上线等位小程序预估；补偿 = 无授权故不含金额承诺。

## 所属工作流

- 好评感谢回复生成
- 月度口碑报告
