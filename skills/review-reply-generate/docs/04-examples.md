# 使用示例

以下示例的输入均为**真实可跑数据**，输出由模型按 `prompt.txt` 的星级分档策略生成。

---

## 示例 1：批量混合星级（餐饮正餐）

**输入**：`examples/input.json`（5 星酸菜鱼 / 2 星等位 / 3 星上菜慢，共 3 条）

**输出**（要点）：

| # | 档位 | 引用细节 | 策略落点 |
|---|---|---|---|
| R01 | 4-5 星 | 小陈帮忙分鱼 | 具体致谢 + 现熬 4 小时工艺背书 + 新品轻引导 1 次 |
| R02 | 1-2 星 | 等位 40 分钟、孩子饿哭 | 四要素 + 等位小程序整改 + 预留四人桌邀请 |
| R03 | 3 星 | 上菜慢、撤盘不及时 | 双线分灶 + 10 分钟巡台两项改进步骤 + 邀请验收 |

开头句零重复；字数 68/84/71 全部落档；升级信号 0 命中。

---

## 示例 2：单条好评（茶饮小店）

**输入**：

```json
{
  "reviews": "茉莉初雪三分糖绝配，店员还提醒我少冰更好喝，真的！", 
  "policy": "会员群运营中"
}
```

**输出**：58 字好评档 —— 致谢复述「三分糖 + 少冰建议」，补一句「配方是试了 17 次定的」，
轻引导「周三会员日第二杯半价」一次。处置动作 = 记录好评点 → 会员群。

---

## 示例 3：升级信号拦截（对照组）

**输入**：

```json
{
  "reviews": "吃出头发丝，已经打 12315 了"
}
```

**输出**：**不生成公开回复**。转人工清单：评价 R-12315，触发信号「12315」，建议动作 =
店长 2 小时内电话联系 + 后厨帽发网自查记录留证 + 向平台报备。批次质量自检标注「剔除 1 条」。

---

*输出为 AI 生成内容，发布前须经店主确认；评价换礼类表述一律不生成。*
