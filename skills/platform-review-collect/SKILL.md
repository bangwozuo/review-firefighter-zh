# 平台评价采集

## 元信息

| 字段 | 值 |
|------|-----|
| ID | `de_local_02_sk01` |
| 类型 | **`atomic`（原子技能）** |
| 所属员工 | 口碑捍卫者 |
| 能力族 | 连接调度型 · 只读采集（T4） |
| 复杂度 | `M` |
| 阶段 | `P0` |
| 复用度 | 高（评价采集分级、月度口碑报告、日报分析师共用） |
| 资产形态 | 纯提示词 + SOP（无运行时依赖，连接执行由商家在平台完成） |

## 能力描述

美团/点评/抖音三平台评价的采集调度 SOP。双通道设计：**通道 A** = 开放接口只读授权
（增量拉取 ≤ 30 分钟一次，守住差评 2 小时黄金响应窗口）；**通道 B** = 商家后台人工导出
（T+1 新鲜度，标注延迟）。统一 8 字段映射（评价ID 幂等去重、星级、正文、订单号、
回复状态等），每日 09:00 对账补漏，每月 1 日归档全量。含异常降级清单（双通道中断时
输出采集中断报告，不编造数据）与合规红线（只读采集、不爬虫、不删改评价）。

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `platforms` | array | ✅ | 采集平台列表：美团 / 点评 / 抖音 |
| `channel` | string | ⬜ | A=开放接口只读 / B=人工导出降级，缺省 A |
| `frequency` | string | ⬜ | 采集频率，建议 ≤ 30 分钟 |
| `last_success_at` | string | ⬜ | 上次成功采集时间（增量起点） |

## 输出规格

- `field_map`：三平台统一字段映射（读/读写方向标注，写操作仅限人工确认的回复）
- `operation`：用户需在平台执行的操作清单（授权绑定 / 导出 / 对账）
- `summary`：采集结果汇总（各平台星级分布、未回复差评数、通道与新鲜度）
- `degraded`：采集中断/降级清单；`limitation`：能力边界声明

## 使用步骤

### 方式一：直接使用（最快）

1. 打开任意支持自定义提示词的 AI 工具
2. 复制 `prompt.txt` 的**全部内容**作为系统提示词
3. 提供平台列表、通道选择、上次采集时间
4. 得到采集配置单 + 字段映射 + 操作清单

### 方式二：在主流平台导入

| 平台 | 导入方式 |
|------|---------|
| **Coze / 扣子** | 新建 Bot → 人设与回复逻辑 → 粘贴 `prompt.txt` |
| **WorkBuddy** | 新建 Skill → 填入 `prompt.txt` 内容 |
| **Dify** | 新建应用 → 提示词编排 → 粘贴 `prompt.txt` |

### 人工确认点（T4 必读）

1. 首次授权绑定门店：店主在商家后台完成，本资产不接触账号密码
2. 回复发布动作：采集为只读，回复经合规审核后由人工发布

## 边界（不做的事）

- ❌ 不真实读写平台系统——只产出字段映射与操作清单，连接由商家执行
- ❌ 不使用爬虫抓取，不超平台接口配额
- ❌ 不删改评价（平台无此接口，声称可删评的服务均违规）
- ❌ 接口失败不编造数据，输出采集中断清单
- ❌ 不采集评价之外的客户个人信息

## 调用示例

**输入**（`examples/input.json`）：

```json
{
  "platforms": ["美团", "点评", "抖音"],
  "channel": "A",
  "frequency": "每 30 分钟增量，每日 09:00 对账",
  "last_success_at": "2026-09-30 08:30"
}
```

**输出**（要点）：采集配置单（三平台通道 A、30 分钟增量）+ 8 字段映射 +
「美团 3 条（差评 1 未回复）/ 点评 2 条（好评 2）/ 抖音 1 条（中评 1）」汇总 +
抖音接口限流降级建议（转通道 B 人工导出）。

## 所属工作流

- 评价采集与分级
- 月度口碑报告

## 合规声明

- 本技能输出为 **AI 辅助生成内容**，采集配置变更需店主确认
- 只读采集与人工确认回复；数据使用遵守《个人信息保护法》最小必要原则
- 平台接口权限以官方最新协议为准
