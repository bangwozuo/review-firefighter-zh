# 使用示例

以下示例的输入均为**真实可跑数据**，输出由模型按 `prompt.txt` 的 SOP 方法论生成。

---

## 示例 1：三平台通道 A 常规采集

**输入**：`examples/input.json`（美团/点评/抖音，通道 A，30 分钟增量）

**输出**（要点）：采集配置单 + 8 字段映射 + 汇总（美团 3 条含 1 条未回复差评 /
点评 2 条好评 / 抖音 1 条中评）。未回复差评推送差评灭火流程；抖音接口限流 →
输出降级建议转通道 B。

---

## 示例 2：通道 B 降级（接口未开通）

**输入**：

```json
{
  "platforms": ["美团", "点评"],
  "channel": "B",
  "frequency": "每日 09:00 人工导出",
  "last_success_at": "2026-09-29"
}
```

**输出**（要点）：配置单标注「通道 B，T+1 新鲜度」；操作清单改为：① 商家后台
「评价管理」导出昨日 Excel；② 按约定目录命名放入；③ 09:00 对账。汇总新增
「新鲜度」列，差评响应窗口按「发现即响应」执行并在灭火流程中标注延迟风险。

---

## 示例 3：双通道中断（对照组，不编造数据）

**输入**：

```json
{
  "platforms": ["美团"],
  "channel": "A",
  "frequency": "每 30 分钟增量",
  "last_success_at": "2026-09-28 14:00",
  "error": "token 过期，刷新失败"
}
```

**输出**：**零评价数据输出**。采集中断清单：平台=美团，状态=token 过期，
最后成功时间=2026-09-28 14:00，建议动作=店主 2 小时内重新授权（超 24 小时中断
将错过差评响应窗口，建议同步开启通道 B 应急）。明确声明不编造任何评价数据。

---

*输出为 AI 生成内容；采集配置变更需店主确认，平台接口权限以官方协议为准。*
