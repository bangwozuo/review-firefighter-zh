# 使用示例

以下示例的输入均为**真实可跑数据**，输出由模型按 `prompt.txt` 方法论生成，并按其质量自检项核对。

---

## 示例 1：价格 + 服务双根因（餐饮，26 元订单）

**输入**：

```json
{
  "reviews": "分量越来越少了，一份牛肉面就三片牛肉，价格还涨了，等了 25 分钟才上桌，不会再来了",
  "root_cause": "",
  "policy": "可发优惠券，单张最高 15 元；小额退款需店长批",
  "order_amount": 26
}
```

**输出**：

| 项 | 内容 |
|---|---|
| 主根因 | 价格（叠加服务）；按「质量 > 服务 > 物流 > 期望差 > 价格」本例无质量异议，取价格为主、服务带过 |
| 命中依据 | 「三片牛肉」（分量）「价格还涨」（价格）「等了 25 分钟」（服务） |
| 公开回复 | 您好，看到您反馈的三片牛肉与 25 分钟等位问题，很抱歉这次没有做好。门店上周已恢复牛肉面 150g 出餐克重并增加高峰期双人出餐。方便的话请私信店长，我们核实后处理。 |
| 私信话术 | 已把您的情况记录给店长，这单我们补一张 10 元券（30 天有效），欢迎您再给一次机会，我们按标准克重重做一份。 |
| 补偿方案 | 10 元无门槛券 —— 落在 <50 元档（5-10 元），未超 15 元授权 |
| 需人工确认 | ✅「恢复 150g 出餐克重」整改动作需确认已执行后才可发布 |

## 示例 2：质量根因（外卖，68 元订单）

**输入**：

```json
{
  "reviews": "酸菜鱼里吃出塑料膜，打电话过去店里一直没人接，太恶心了",
  "order_amount": 68,
  "policy": "全额退款授权已开通"
}
```

**输出**：

| 项 | 内容 |
|---|---|
| 主根因 | 质量（异物 + 无人接听的服务次因） |
| 公开回复 | 看到您在酸菜鱼中发现异物，非常抱歉。后厨今早已停用该批次 packaging 并逐袋排查，出餐前增加二次目检。请您私信订单号，我们全额退款并上门致歉。 |
| 补偿方案 | 全额退款 68 元（50-200 元档 10%-20% 档的上限处置——异物类直接顶格） |
| 需人工确认 | ✅ 涉及退款与「停用批次」事实核对 |

---

## 示例 3：升级信号（不套模板）

**输入**：

```json
{
  "reviews": "吃完全家三个人都拉肚子，已经打 12315 投诉了，等处理结果",
  "order_amount": 210,
  "policy": "转人工"
}
```

**输出**：

| 项 | 内容 |
|---|---|
| 判定 | 命中升级信号「12315」+「食安中毒」—— 不生成常规话术 |
| 升级动作 | 立即转人工/法务：留存同批次留样与进货凭证、2 小时内电话联系客户、向平台报备食安投诉 |
| 补偿方案 | 不在线上承诺；>200 元档由专人电话沟通 |

---

*输出为 AI 生成内容，发布前须经店主确认；平台评价规则以官方最新公示为准。*
